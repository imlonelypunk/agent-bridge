# Автономний обмін між агентами з доступом до репозиторію

Автор: Claude (архітектурна пропозиція). Дата: 2026-11-10. Статус: чернетка на рішення власника, реалізує Codex.
Розділи 1–8 нижче — історична пропозиція окремого працівника, не опис реалізованої функції. Твердження про неможливість пробудження Codex у цих розділах застаріли; актуальний стан описано в розділі 0 і README.
Перевірено читанням коду гілки `codex/antigravity-ide-inbox` (коміт `1beef46`) і службових полів скриньки. Прапорці CLI перевірені лише для `claude` 2.1.292; для `codex` і `agy` їх треба звірити з установленими версіями.

## 0. Що вже зроблено: живий чат через слухання скриньки (гілка `claude/live-inbox`)

Власник обрав живий чат: відповідає відкрита сесія агента з її контекстом. Розширення не може вставити текст у чужий чат, тому сесія слухає скриньку сама.

- `wait_inbox` — інструмент MCP у повному мості й у плагіні: чекає до 50 секунд на наступне непрочитане вхідне, повертає його або `idle`.
- `watch` — довга форма для командного рядка: блокує до нового повідомлення, друкує його і завершується (код 3, якщо нічого не прийшло). Claude Code будить сесію, коли фонова команда завершується, тож очікування нічого не коштує.
- Відповідь, яку вже повернув `wait_reply`, вдруге не пропонується.

Перевірено 10 листопада на тестовій скриньці: сесія Claude чекала у фоні, отримала запитання про рядок 72 файлу з репозиторію мода, прокинулась без участі власника, прочитала файл і відповіла; відправник отримав відповідь через `wait_reply` за 13 секунд після надсилання. Запитання надсилав сам Claude в ролі `codex`; справжній Codex у перевірці участі не брав. 22 тести проходять.

Як слухає кожен агент:

| Агент | Спосіб | Стан |
|---|---|---|
| Claude Code | `watch` у фоні, сесія прокидається сама | Перевірено в живій сесії |
| Antigravity | Розширення саме вставляє запит у чат (`agentBridge.autoAntigravity`) | Було раніше; у поточну розмову замість нової — не перевірено |
| Codex | `postman`: окремий процес чекає на вхідне і кладе коротке сповіщення в чергу наявної сесії через `codex queue --thread … --resume` | Перевірено 10 листопада зі справжнім Codex: у його транскрипті хід із `turn_trigger: queue` почався о 20:50:44 UTC, відповідь у скриньці о 20:50:53, без участі власника |

Сповіщення для Codex містить лише відправника, тип і номер повідомлення. Тіла там немає навмисно: текст із черги Codex сприймає як слова користувача, а саме повідомлення він читає через свої інструменти мосту як неперевірені дані. Нотатки сесію не будять. Після 12 пробуджень `postman` зупиняється, щоб два агенти не ганяли одне одного без нагляду.

Запобіжник для живого чату суворіший, ніж для фонової сесії: слухач має повні права, тому вхідне повідомлення — це запит колеги й неперевірені дані. Відповідати на запитання можна, а зміну файлів, команди з наслідками й надсилання файлів підтверджує власник. Це записано в навичці `plugin/skills/agent-bridge/SKILL.md`.

Фонова сесія в теці репозиторію (розділ 4) лишається запасним шляхом, коли живої сесії адресата немає.

## 1. Чого хоче власник

Codex, Claude Code і Antigravity самі надсилають одне одному запити й відповіді, бачать репозиторій, і все це працює на рівні розширення, без перенесення тексту руками.

## 2. Чому зараз так не виходить

| Причина | Де в коді |
|---|---|
| Разова консультація (`dispatch --surface headless`) запускає CLI у тимчасовій теці, вимикає інструменти читання і прямо каже «використовуй лише наданий контекст». Тому Argon відповідав, що не бачить файлів: так задумано. | `bridge_runner.py`: `TemporaryDirectory(prefix="kinesis-reply-")`, `check_isolated_workspace`, `prompt_for`; для `claude` — `--tools ""` і `--max-turns 1`, для `agy` — заборона `read_file`, для `codex` — `--disable shell_tool` |
| Ліміт 240 секунд і один хід не дають агентові нічого прочитати, навіть якби файли були. | `bridge_runner.py`: `TIMEOUT = 240` |
| Доставка у відкритий чат автоматична лише для Antigravity, через три недокументовані команди IDE. | `ide-extension/extension.js`: `antigravity.startNewConversation`, `addContext`, `triggerSend` |
| Claude Code отримує лише заготовку, де треба натиснути Enter; Codex — текст у буфері обміну. Їхні розширення не дають стороннім надіслати повідомлення в чат. | `extension.js`: `openInIde` |
| Разова консультація для Codex, найімовірніше, не стартує: `codex.exe` лежить у `%LOCALAPPDATA%\OpenAI\Codex\bin\<хеш>\`, а в `PATH` перевіреної оболонки його немає. У скриньці є записи доставки для Claude (10) і Antigravity (8) і жодного для Codex; сам запуск я не пробував. | `bridge_runner.py`: `executable` |
| Власник працює в застосунках Codex і Claude, а не в їхніх розширеннях VS Code. Розширення VSIX до чатів цих застосунків не дотягується взагалі. | — |

## 3. Що можливо для кожного агента

| Агент | Автоматично вставити запит у відкритий чат | Автоматично відповісти з доступом до репозиторію |
|---|---|---|
| Antigravity | Так, уже є (`agentBridge.autoAntigravity`), але на недокументованих командах | Так: чат IDE відкритий на репозиторії; або `agy` у теці репозиторію |
| Claude Code | Ні: публічного способу надіслати повідомлення в чужий чат немає | Так: `claude --print` у теці репозиторію з інструментами лише для читання |
| Codex | Ні: те саме обмеження | Так, якщо `codex exec` запустити в теці репозиторію з пісочницею лише для читання; шлях до `codex.exe` треба знаходити явно |

Висновок: «агент у відкритому чаті сам побачив запит» досяжно тільки для Antigravity. Для всіх трьох досяжно інше: запит автоматично обробляє окрема фонова сесія того самого агента, запущена в теці репозиторію.

## 4. Рішення: третя поверхня доставки `repo`

Поруч з `ide` і `headless` додати поверхню `repo` — «працівник репозиторію».

Потік:

1. Відправник викликає `send` або `dispatch --surface repo` і чекає через `wait_reply`.
2. Розширення в будь-якому відкритому вікні IDE з цим репозиторієм опитує скриньку, бере повідомлення за ключем репозиторію і резервує його (`claim_ide` уже захищає від подвійної обробки).
3. Розширення запускає CLI адресата з робочою текою = корінь репозиторію, з правами лише на читання.
4. Вихід CLI стає відповіддю (`reply` з `reply_to`), як це вже робить `bridge_runner.py`. Сесії-працівникові власний профіль MCP не потрібен.
5. Відправник отримує відповідь через `wait_reply`; якщо він не чекав, вона лежить у скриньці, а в Antigravity відкривається автоматично.

Деталі:

- **Одне вікно обслуговує всі ролі.** Працівник — це запуск CLI, тому одне розширення (наприклад, в Antigravity IDE) може відповідати за `claude`, `codex` і `antigravity` одразу. Нове налаштування: `agentBridge.workerRoles`.
- **Права.** `claude`: `--print`, `--permission-mode plan`, `--allowed-tools Read,Grep,Glob`. `codex`: `exec --sandbox read-only` з увімкненим читанням. `agy`: `--mode=plan --sandbox`, заборонити запис, команди, мережу й MCP, дозволити `read_file`.
- **Час і ходи.** Прибрати обмеження в один хід, ліміт часу 10–15 хвилин; `wait_reply` викликається повторно.
- **Пам'ять між запитами.** Для пари «роль + репозиторій» зберігати ідентифікатор сесії і продовжувати її (`claude --resume <id>` є; для `codex` і `agy` перевірити). Сесія коротшає примусово після N запитів, щоб контекст не розростався.
- **Спільний стан.** Працівник не знає, що відбувається в живому чаті того самого агента. Усе, що він має знати, лежить у репозиторії: дошка, передача, документи. Запит має посилатися на файли, а не на «те, про що ми говорили».
- **Шлях до CLI.** Налаштування `agentBridge.cliPaths` і пошук `codex.exe` у відомих теках установки.

## 5. Обов'язкові запобіжники

1. **Тільки читання за замовчуванням.** Вхідне повідомлення — це дані, а не дозвіл. Запис у файли, команди й мережа вимкнені. Задачі із записом ідуть через дошку й живу сесію власника.
2. **Список дозволених репозиторіїв.** Поточний код навмисно відмовляється працювати в теці з `.git` чи власними хуками, бо там може виконатися чужий код. Режим `repo` вмикається явно для кожного репозиторію; хуки й плагіни проєкту в працівнику вимкнені, де CLI це дозволяє.
3. **Захист від зациклення.** Відповідь ніколи не породжує автоматичну відповідь. Ліміт кроків у ланцюжку (наприклад, 4), один запит у роботі на пару «роль + репозиторій», денний ліміт запусків на роль. Без цього агенти можуть спалити ліміти підписок, поки власник не дивиться.
4. **Секрети.** Не віддавати працівникові `.env`, ключі й усе, що в `.gitignore`.
5. **Журнал.** Кожен запуск пише, хто спитав, що було прочитано і скільки це тривало; тексти лишаються в скриньці.

## 6. Чого це не дає

- Живі чати в застосунках Codex і Claude самі запит не побачать; відповідає фонова сесія.
- Кожен запуск витрачає ліміти відповідної підписки.
- Автоматична вставка в Antigravity може зламатися з оновленням IDE.

## 8. Рішення власника

1. Чи приймається фонова сесія в теці репозиторію як «автоматична відповідь», якщо живий чат недосяжний.
2. Чи достатньо режиму «лише читання» на початку.
3. Які репозиторії дозволити першими (мод Victoria 3, AgentBridge, Kinesis).
4. Денний ліміт запусків на кожного агента.
